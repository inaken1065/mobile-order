# スケーラビリティ・容量・コスト設計: mobile-order の Google Cloud デプロイ

## Sources

- `[memory:M1]` `scalability-requirements.md`(NFR1.1〜1.6、NFR4.4)と `requirements.md` の Out of scope(スケールアウトとオートスケールは範囲外)
- `[assumption]` 利用者は自分だけ(`requirements.md` の A2、A6)

## 方針

スケールアウトとオートスケールは設計しない。VM 1 台、SQLite のまま、縦にも横にも伸ばさない。この文書で設計するのは、容量の見張りと、コストの上限を守るための統制である。

## コストの統制

| 項目 | 設計 | 要件 |
|---|---|---|
| 月額の上限 | 見積もりの表の合計を 5 ドル以内に保つ。`apply` の承認のたびに表を更新して示す。現時点の見積もりは約 3.65 ドル(外部 IPv4 のみ) | NFR1.1 |
| 構成の固定 | us-central1、e2-micro 1 台、標準永続ディスク(ブートとデータの合計 30 GB 以内)。これ以外(別のマシンタイプ、SSD、30 GB 超)を含む `plan` は、承認の前に差分として指摘する | NFR1.2 |
| 外部 IPv4 の料金 | 約 0.005 ドル / 時間は未確認の数値。`apply` の承認の前に公式の料金ページで再確認し、承認の記録に日付と数値を残す。確認できない、または 5 ドル超なら、見積もりを更新して承認を取り直す | NFR1.3 |
| 外部 IP | エフェメラルを採用。`google_compute_address` を作らない(`plan` に出ない) | NFR1.4 |
| 外向き通信 | 無料枠の 1 GB / 月に収まる前提。月次の請求確認で、通信の料金が 1 ドル未満であること | NFR1.5 |
| 片付け | VM、外部 IP、ディスクを削除して課金を止める手順を手順書に書く。データディスクを残すかは、実行時に人間が選び承認する | NFR1.6 |
| データディスクの保護 | VM とは別の Terraform リソースにし、`prevent_destroy` を付ける。通常の再構築では消えない。完全削除は、別の手順書で、承認つきで行う | NFR4.4 |

## 容量の見張り

- データ量は数 MB 以下の見込み。ディスク使用率が 80% を超えたら、手順書に従って確認する(`df -h`)。
- 同時利用は自分だけ。複数端末の同時利用は、既存のポーリングの動作を変えず、扱わない。

## 上限を超えたときの方針

- 利用者が増える、データが 1 GB を超える、といった前提の崩れが起きたら、この設計の範囲外とし、別の作業として設計し直す。

## Assumptions & Open Questions

- `[assumption]` A1: データ量は、学習用の期間中に 1 GB を超えない。
- 未確定: Cloud Storage の state バケットの無料枠(Standard クラスの 5 GB が、使うリージョンの対象か)は、実施時に公式情報で再確認する(要件定義の A5)。
