# 信頼性・復旧要件: mobile-order の Google Cloud デプロイ

## Sources

- `[Q5]` 数値の SLO は設けない。目標は自動再起動と自動ロールバックだけ。`nfr-requirements-questions.md` の回答
- `[memory:M1]` `requirements.md` の NFR3（復旧）、NFR4（再現性）、FR2.3〜FR2.5（起動、ディスク、シード）、FR5.4（ロールバック）
- `operation.md`（フェーズのルール）: SLO は数値で、ロールバックとスモークテストを備える

## 方針

利用者は自分だけの学習用で、バックアップは取らない（`requirements.md` の NFR3）。数値の SLO（可用性の割合）は設けず（`[Q5]`）、次の「自動で戻る」2 点を信頼性の目標にする。operation フェーズのルールにある「SLO は数値で」は、数値の可用性を設けないことを、人間が選んだ判断として記録して対応する。

## 受け入れたリスク

- 数値の可用性（SLO）がないため、停止の長さに上限がない。VM の障害や、デプロイ中の数秒〜数十秒の停止は許容する（`requirements.md` A2）。
- バックアップがないため、ディスクの障害でデータは失われる（NFR3.5 で、シードから作り直す）。
- 単一の VM と単一のゾーンのため、ゾーンの障害で止まる。

## Assumptions & Open Questions

- `[assumption]` A1: 自分以外の利用者に影響しない。停止しても、業務への影響はない。
- 未確定: デプロイの方式（成果物の置き方、切り替え、世代の管理）の詳細は、後の設計ステージで決める。
