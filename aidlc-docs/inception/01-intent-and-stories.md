# Intent & User Stories

## Intent
飲食店向けモバイルオーダー。客がスマホで注文し調理状況を確認、厨房がステータスを進め、店長がメニューと売上を管理する。
**学習目的**: AI-DLC の「ユニット分割」と「Bolt 並列実行」の体験(プロダクトの完成度は二の次)。

## スコープ(学習用に絞る)
- 含む: 注文〜調理〜完成の一連フロー、メニュー管理、日次売上
- 含まない: 決済、認証の本格実装(ロール切替はヘッダ/URL で代用)、複数店舗、アレルギー管理

## ステータス遷移
`受付(PLACED)` → `調理中(COOKING)` → `完成(READY)` ※受け渡し済みは対象外(完成で終端)

## User Stories

### 客
- C1: メニュー一覧(カテゴリ別、売り切れ表示)を見られる
- C2: カートに入れて注文できる(卓番号 or 呼出番号を受け取る)
- C3: 注文のステータスをリアルタイム(ポーリング可)で確認できる
- 受入: 売り切れ商品は注文不可。注文時点の価格で確定する

### 厨房
- K1: 新規注文が古い順に一覧表示される
- K2: 注文を「調理中」に進められる
- K3: 注文を「完成」に進められる(逆戻り不可)

### 店長
- M1: メニューの追加・編集・価格変更ができる
- M2: 売り切れの ON/OFF を即時反映できる
- M3: 日次売上(合計、件数、商品別数量)を確認できる
- 受入: 売上は「完成」した注文のみ集計

## 非機能(最小)
- ユニットはロール単位の縦割り。API サーバー1つ・SQLite 1つを共有し、結合は契約とスキーマで固定する
- 技術スタック既定: TypeScript / Fastify / SQLite / React(Vite)。変更可
